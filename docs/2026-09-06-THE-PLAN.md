## 2. GLOSSARY — every term, defined once

**the film** — `src/film/Film.tsx` and everything it renders. Scroll drives a paused GSAP timeline `tl`;
`tl.time()` is the film clock `t`, from 0 to 66. `window.__film = { world, tl, camera }` is exposed for
measurement (see `Film.tsx`, search `__film`).

**stage / scene (S1 … S8)** — the eight chapters of the film. Scene book §3 lists them beat by beat.
Time ranges: S1 t0–10.2 · S2 t10.2–16.5 · S3 t16.5–26.5 · S4 t26.5–36 · S5 t36–50 · S6 t50–57.5 ·
S7 t57.5–64.5 · S8 t64.5–66.

**set module** — one of `src/film/sets/*.ts`: `ambush` (S1 camp), `pathProps` (S3 props), `ground`
(islands and forest), `theatre` (S4), `tavern` (S5), `montage` (S6), `cliffWorld` (S7), `board`,
and `kit.ts` (shared builders used by the sets). `src/film/world.ts` only composes them (109 lines, `wc -l`).
No set imports `world.ts` (`grep -l "from '../world" src/film/sets/*.ts` → none); the rig contract lives in `src/film/rig.ts`.

**hero / the hero island** — the accepted reference build, `src/film/stages/hero.ts`. When this file
says "like the hero", it means: render your thing next to the hero island and they must look drawn by
the same hand.

**Performance rig vs Prep rig ("both rigs")** — two lighting/render states of the same scene.
*Performance* = painted, lit, colour. *Prep* = the graphite underdrawing, no light. `?rig=prep` on a
mock route shows Prep. `window.__curtain.value = 1` forces Prep in the film; `0` forces Performance.
Every surface must read correctly in BOTH.

**curtain / seam** — the transition between Prep and Performance. `uTriCurtain` fades the whole page;
`rig.seamX` is a vertical world-x line where everything EAST (larger x) is Prep. The seam is **parked**
(value `1e6`, see `stages/trilayer.ts` search `seamX`) for the whole film except where `timeline.ts`
stages it. Do not touch seam code.

**trilayer** — the shader in `src/film/stages/trilayer.ts` that gives every Lambert surface its paint
layer, its graphite underdrawing and its edge wear. Every painted mesh in the film uses it.

**triAlbedo / tier / triTone / the quantizer** — the trilayer reads the surface colour AFTER the texture
map is applied (`triAlbedo = diffuseColor.rgb` on the line right after `#include <map_fragment>`; search
`triAlbedo`). So the colour it sees is `material.color × texture pixel`. It then bins luminance into
4 tiers with boundaries at **triTone 0.14 / 0.30 / 0.46 / 0.62** (`step(0.14, triTone)` and `floor((triTone − 0.14) *
6.25)`, i.e. 0.16 per tier — grep `triTier` in trilayer.ts). World noise adds ±0.03: the line reads
`triTone = 1.0 − triT + (triNoise(…) − 0.5) * 0.06` (grep `* 0.06`; searching for "0.03" finds nothing). Formula (art bible §11.3):
```
lin(c)  = c <= 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055) ^ 2.4     (c = sRGB byte / 255)
lumLin  = 0.2126 lin(R) + 0.7152 lin(G) + 0.0722 lin(B)
enc(x)  = x ^ 0.4545
triT    = (enc(lum(albedo)) − enc(lum(ink))) / (enc(lum(paper)) − enc(lum(ink)))
triTone = 1 − triT
```
paper = `#F7F5F0`, ink = `#222222`. **Use the exact piecewise sRGB curve above, never `x^2.2`.** Three
decodes hex colours with the piecewise curve, so the shortcut is off by ~0.01 and produces false
"corrections" (verified 2026-09-06 against seven committed bible values: only the piecewise curve
reproduces all seven; `enc(lum(ink)) = 0.15266`). A pigment is legal only if its triTone is more than
0.03 away from every boundary. Compute it with the multiply included. See §4.3 for the procedure.
The canonical script is `story/story/scripts/tritone.mjs` (P0e + P0i). Modes: `node scripts/tritone.mjs <hex>` ·
`mix <hexA> <hexB> <t>` · `stop <hex> <g> [g2 …]` (token × grey bake stop, per channel lin×lin, min distance across
stops) · `mul <hexA> <hexB>` (token × coloured texel, prints CLIP if a channel exceeds 1.0). It self-checks the
multiply method against P0h's measured stoneCool stops on every run and exits 1 if the method drifts. Do NOT use any
scratchpad `tritone*.mjs` from an earlier agent: one of them uses `x^2.2`. Before trusting any script,
check it prints `encInk 0.15266` and `triTone(#CFDDDF) = 0.1335`.

**token / pigment / `P.xxx`** — a named colour in `src/film/palette.ts` (exported as `P`). "Never a
fresh hue" (§3 law 5) means every colour on screen is a `P` token or `mixHex(P.a, P.b, t)` of two
tokens. Kits export committed mixes (e.g. `GRASS_LIT`, `CLIFF_SHADE`, `BOARD_WATER`, `CAST_STEEL`,
`humanFace`). Use those before mixing your own.

**key / key family** — the directional light colour. Three families, set by `timeline.ts` at scene cuts:
`keyNight #BBB2BB` (S1, S2) · `keyDay #FAF2E6` (S3, S4, S6, S7) · `keyWarm #FFEACC` (S5 interior).
The film's rig is `FILM_RIG` in `stages/rigs.ts` (hemisphere 1.45) rendered by `Film.tsx`. The OTHER rig
in the same file (`HEMI_I = 0.8`) is the hero's standalone rig. When measuring in the film, the film's
rig is what lights you.

**kit / class / mock route** — 22 "surface classes" (rock, strata, foliage, cloth, snow, water …)
each proven as a module in `src/film/mock/<class>.ts` and viewable at `http://localhost:5180/?mock=<class>`
beside a piece of the hero island. The shared builders those modules use live in
`src/film/mock/*Kit.ts` (`groundKit`, `foliageKit`, `plankKit`, `marksKit`, `clothKit`, `fire.ts`, and since 2026-09-06
`hideKit` (monster, raven geometry), `machineryKit`, `skyKit` — `ls src/film/mock/*Kit.ts`).
Class ids: `ground incident rock strata field foliage bark timber plank metal paperprop sky snow water
fire glass cloth hide marks machinery drawnsheet board`. `?mock=sheet` tiles all of them.
`?mock=transfer` is the §4.7 colour probe. Options: `&rig=prep`, `&zoom=1..6`, `&family=…`.

**ground card / incident card / skirt / rim contour** — the proven way an island is built
(`groundKit.ts`: `buildGroundCard`, `buildIncidentCard`, `buildSkirt`, `rimContour`, `propGround`).
The **skirt** is the drawn section under the island edge. **C1** says its depth is ONE formula:
`skirtD(rz) = clamp(rz · 0.439, 0.5, 2.6)` (exported as `skirtD`). The **rim contour** (C2) is an open
drawn arc with one unfinished gap, never a closed loop.

**grounding / contact blob** — a painted dark patch baked into the ground under every painted prop so
it sits ON the ground instead of floating. Done with `propGround(rx, rz, blobs)` from `groundKit.ts`,
where `blobs` comes from `contacts([...])` in `sets/kit.ts`. **Name collision warning:**
`contacts()` (plural, `sets/kit.ts`) is the GOOD grounding helper. `contact()` (singular,
`src/film/pencil.ts`) is a BANNED nine-stroke hatch. Do not confuse them.

**hatching** — two or more families of parallel strokes crossing each other to make tone. BANNED
everywhere (law 2). Legal: isolated crossings where one contour meets another (≈4 per pine on the hero).
Hidden hatching lives inside helpers: `hatch()`, `crossHatch()`, `contact()`, `rays()` in `pencil.ts`.
Every call to those four is a "retirement site" and must go to zero.

**basis / view plane / `setView`** — art bible §3.6: pencil marks are flat strokes authored in a plane
facing the CAMERA OF THE SHOT they appear in. `foliageKit.ts` keeps a module-level basis
(`VIEW_R`, `VIEW_CAM`); `setView(az, elev)` points it at a shot; `setView()` with no args restores the
hero's lens. A builder that draws marks without first calling `setView` for its shot draws them facing
the hero's camera, and in a different shot the strokes fly off the mass. See §4.4.

**PRNG order** — `src/film/pencil.ts` has ONE global random seed (`let seed = 0x9e3779b9`, search
`let seed`) that is never reset. Every pencil mark in the film depends on the exact ORDER every builder
runs. If you reorder builder calls, every stroke in the film changes. Add new builders at the END of
a set's build, never in the middle, unless your unit says otherwise.

**poster / poster steps** — the number of tone bins the Prep (graphite) bake uses. The film renders 12.
A mock route rendering 8 judges against a different quantizer than the film.

**walk / frame** — a screenshot of the film or a mock route at a known `t`, rig and zoom, saved to
`docs/build/walks/world/`. Frames are the only evidence that counts. See §4.1.

### 4.3 Prove a pigment is legal (the triTone check)

1. Find the material colour (`material.color` or the `color:` argument) AND the texture it multiplies
   (the `bake*` function that built the `CanvasTexture`). If the material is built white
   (`0xffffff`) and the texture carries the colour, the albedo is the texture pixel. If BOTH carry
   colour, the albedo is their product per channel, in linear — that is the "pigment squared" trap.
2. Compute triTone for the DARKEST and the LIGHTEST pixel the texture can produce, after the multiply,
   with `node scripts/tritone.mjs stop <tokenHex> <g>` (P0i). **How the multiply works (measured under
   P0h, 2026-09-06):** a bake's grey stop `grey(g)` is an sRGB texel like any other, so the on-screen
   linear albedo per channel is `lin(token) × lin(g)`, NOT `lin(token) × g`. Using `× g` is off by ~0.08
   in triTone and reproduces nothing. A texture with hue (canopy, bark, plank grain) multiplies per
   channel the same way: `lin(token) × lin(texel)`.
3. Pass = both values are > 0.03 away from 0.14, 0.30, 0.46 and 0.62, AND the tier they land in is the
   tier the art bible row specifies.
4. Write the numbers in your report: hex, linear lum, triTone, tier, distance to nearest boundary.

### 4.4 Prove the basis (§3.6) for a shot

**CORRECTED 2026-09-06 (T-BASIS, `scripts/measure/basis-check.mjs`).** The formula this section used to give,
`az = atan2(cz−fz, cx−fx)`, is in a DIFFERENT azimuth convention from `setView` / `setMarksView` and lands
the view plane ~90° off the camera (marks render edge-on as slivers). The kits' own math is the hero's camera
formula and is correct. **Never hand-derive a basis.** Use the shared helper:
```ts
import { shotView, setView } from '../mock/foliageKit.ts';      // marksKit re-exports the same shotView
const v = shotView([cx, cy, cz], [fx, fy, fz]);                 // az = atan2(dx, −dz), elev = atan2(dy, hypot)
setView(v.az, v.elev);  /* build marks */  setView();           // or setMarksView(...) for marksKit marks
```
`shotView(heroCam, heroLook)` reproduces `HERO_AZ / HERO_ELEV` to 0.0°. `ground.ts`'s `C2_AZ / C2_ELEV` were
derived natively and are right. Fixed 2026-09-06: `kit.ts` now has `const IMPACT_VIEW = shotView([114.4, 7.2, 3.0],
[117.6, 6.4, 0])` and `cliffWorld.ts` has `CAM4_VIEW` / `CUT75_VIEW` from `shotView` (grep `shotView(` in both).

### 4.5 Count crossings (the hatching gate)

1. Get the mark geometry as world-space segments (traverse `window.__film.world.root`, collect
   `LineSegments2` positions, apply `matrixWorld`).
2. Project every segment through the shot's camera to screen px.
3. Count intersections between segments from DIFFERENT strokes. Exclude joint overshoot: `strokes()`
   in `pencil.ts` extends each segment end by `min(len·0.06, 0.05)`, so two segments sharing an
   endpoint always overlap. Skip pairs whose intersection is within that overshoot of either endpoint.
4. Report crossings per object. Compare against the hero's pine (~4 per tree when projected through
   `heroFraming(1440, 900)`). More than that on a same-sized object = hatching = FAIL.

### 4.6 The look loop (the actual work)

render → LOOK at the picture → change one thing → render. Minimum TEN rounds, in BOTH rigs, at TWO
zooms, with a piece of the hero island in the same frame. Every round writes a frame to disk (§4.1
step 7). A verifier once wrote: *"Thirteen iterations were claimed. One frame is on disk."* That is a
failed unit. Reasoning about code instead of looking at pixels is how every failed round failed.

### 4.7 Retire a hatching site
