2026-09-03. Every recipe below is running on screen at `?hero=1` and on the film's front
door. Nothing here is aspirational. Every claim cites the file and line that implements
it, and where a live document and the shipped code disagree, **the code wins and the

## 1. THE TRANSFER

### 1.1 What the renderer actually does

There is **no tone mapping anywhere in this product**, on either surface, ever.

- **The hero.** `Hero.tsx:259` passes `flat` to the R3F `<Canvas>`. R3F reads that flag at
  `node_modules/@react-three/fiber/dist/events-156d8d12.esm.js:15903`:
  `gl.toneMapping = flat ? THREE.NoToneMapping : THREE.ACESFilmicToneMapping`. Without
  `flat`, R3F installs ACES. The hero says `flat`, so it does not.
- **The film.** `App.tsx:207–213` does **not** pass `flat`, so R3F sets ACES on the
  canvas — and it never bites. `curtain.ts:381–388` records why: three r185 forces
  `NoToneMapping` whenever the renderer targets a render target (non-XR), whatever a
  material's `toneMapped` flag says. The film's world pass renders into `frameTarget`
  (`curtain.ts:363`), so the world is untone-mapped by construction; the one pass that
  reaches the canvas is the curtain composite, and it carries `toneMapped: false`
  (`curtain.ts:388`).
- **Every off-canvas measurement path** matches: `islandKit.ts:109`, `hero.ts:847`
  (glow sprite), `posterBake.ts:51–56`, `gobMeasure.ts` (FloatType / NoColorSpace),
  `IslandSandbox.tsx:270–274`.

Net: **one linear render, one sRGB encode, nothing in between.**

### 1.2 Why nothing may be judged under a tone curve

`IslandSandbox.tsx:269–274` is the record of what happens when someone does: with ACES
on, the sandbox "showed a grey disc that would be graphite-on-PAPER in the film." A
filmic curve compresses the top end, and this film's entire subject is a near-white page
with a small dark subject on it. ACES eats the page.

**Rule.** Any screenshot, any colour pick, any material sign-off taken under a tone curve
is void. If you are comparing values, take them through `window.__gob` (`gobMeasure.ts`)
or the island sandbox's float readback (`IslandSandbox.tsx:161–200`), never off a
screenshot from an unknown pipeline.

### 1.3 What that means for how values are authored

Because there is no curve, **values must be authored in the encoded domain, not the
linear one.** This is not stylistic; it is a bug the codebase has already been bitten by
twice, in the same file, in the same way.

- The underdrawing's tone measures encoded: `trilayer.ts:365–367` divides
  `pow(lum, 0.4545)` differences, "linear luminance crushes every mid and dark paint into
  the same low sliver, and the whole diorama drained into one ~7% band."
- The paint-side quantizer measures encoded: `trilayer.ts:291–293`. The comment at
  `trilayer.ts:265–281` records the failure — the goblin's cloak spans ~0.004–0.05 linear,
  which is inside bin 0 at any usable step count, so a 26-sample scan across the garment
  read `46,46,46,45,45,46,46,46,46,47`. "There is no value of `uTriPoster` that fixes that
  in linear."
- The measurement harness carries both domains and never mixes them:
  `gobMeasure.ts:29–46`. Every field is suffixed `_lin` or `_enc` / `_enc255`, **and every
  published threshold lives in `_enc`.**

**Rule.** When you write a number for a value — a floor, a tier target, a separation gate
— write it as an encoded luminance (0..1, or /255). When you write a number for a mix
weight inside a shader, know that the mix happens in linear and that the encoded response
near a mid field is steeply super-linear. `hero.ts:1807–1825` is the worked example: the
goblin's crossing shadow needed 0.97, not the 0.62 the design doc reasoned to on the page,
because 0.62 delivers 12% of the intended darkening, not 60%.

## 2. SURFACE — the painted trilayer

This is the heart of the document. One material, `createTrilayer()`
(`trilayer.ts:463–552`), carries every world surface. All instances share the rig uniforms
**by identity** and compile to **one program** — `customProgramCacheKey() => 'trilayer'`
(`trilayer.ts:549`). Every per-surface knob is a uniform, not a variant.

The base is `MeshLambertMaterial` (`trilayer.ts:472`) with `material.fog = false`
(`trilayer.ts:480`) — both depth languages are in-material, and scene fog would stack a
second differently-coloured ramp.

### 2.1 The three layers

Every fragment computes two complete results and mixes them by one number.

**Paint (Performance).** The lit Lambert result, plus edge-wear, plus the optional value
quantizer, plus fog-to-paper. `trilayer.ts:282–294, 328–351`.

**Underdrawing (Prep).** Built from `uTriPaper` upward, unlit by construction — it never
reads `outgoingLight`. `trilayer.ts:353–437`.

**Edge-wear.** Composed on the paint side only. `trilayer.ts:282–283`:

```glsl
float triWearF = pow(1.0 - abs(dot(normalize(normal), normalize(vViewPosition))), 2.5);
outgoingLight = mix(outgoingLight, uTriPaper, triWearF * uTriWear);
```

A miniature painter's drybrush: silhouette edges lighten toward **paper**, never toward
white and never toward a highlight colour. Default `wear = 0.22` (`trilayer.ts:465`).

**Wear composes BEFORE the poster, and this ordering is load-bearing.**
`trilayer.ts:276–281`: composed after, the drybrush laid a smooth 26% ramp across every
tier boundary, and the tiers stopped reading as tiers — "no two adjacent samples inside a
bin agreed to 2/255." A dry brush leaves a committed step; the code makes it one.

**The mix.** `trilayer.ts:439`: `outgoingLight = mix(triPaint, triUnder, triC)`, where
`triC = max(uTriCurtain, triSeamF) * (1.0 - uTriAlive)` (`trilayer.ts:326`). Any partial
value is a coherent held frame across every surface **and** the lights, because
`rigs.ts:141` reads the same `{ value }` object.

### 2.2 The tone quantizer — two of them, do not confuse them

There are **two** quantizers with different jobs and different tier counts.

**(a) The paint-side poster.** Opt-in, `poster: N` (`trilayer.ts:284–294`).

```glsl
float triPl = max(triLum(outgoingLight), 1e-5);
float triPe = max(pow(triPl, 0.4545), uTriFloor);   // encoded, with a floor
float triPq = (floor(triPe * uTriPoster) + 0.5) / uTriPoster;
outgoingLight *= pow(triPq, 2.2) / triPl;
```

Hue is kept; only luminance quantizes. `floor` is the darkest **committed** tier as an
encoded luminance — a painted garment bottoms out at the darkest value mixed *for it*, not
at the paper's black (`trilayer.ts:286–290`, `trilayer.ts:449–452`).

**`poster: 0` is the default and it is what most of the hero ships.** The complete census
of shipped poster values:

| Surface | poster | floor | Site |
|---|---|---|---|
| Tree crowns (oak lobes, pine tiers) | 12 | — | `hero.ts:975, 1013` |
| The carpenter's pencil | 6 | — | `hero.ts:1178` |
| Goblin dark cloth | 18 | 0.175 | `world.ts:1069, 1248` |
| Goblin worn cloth | 10 | — | `world.ts:1070` |
| Goblin skin / inner ear / tooth | 12 | — | `world.ts:1071, 1072, 1653` |
| Goblin satchel (leather) | 8 | — | `world.ts:1332` |
| Goblin brass | 8 | — | `world.ts:1538` |
| **Everything else — rock, strata, roots, chest, ground card** | **0** | — | `hero.ts:1084–1093, 1136, 1453, 1482`, `islandKit.ts:88` |

> **CODE WINS — rock tiers.** `world-direction.md:407` specifies rock/cliff as "baked
> gouache in **3 quantized tiers**". No shipped rock or strata band carries a quantizer:
> `buildRock` (`hero.ts:1132–1140`) and the three lathe bands (`hero.ts:1453`) both pass
> `poster` implicitly as 0. Their tiering comes from `roughen()` under the Lambert key,
> not from the shader. Build rock that way.

> **CODE WINS — cloth tiers.** `world-direction.md:410` specifies cloth at `poster: 3`;
> `world-direction.md:992` specifies the cloak at `poster: 10`. Shipped is **18** with a
> **0.175** floor (`world.ts:1069`). The reasoning is at `world.ts:1050–1068`: a dark mass
> needs *more* steps to show a tier, and the count only started working once the quantizer
> moved to the encoded domain. Note also that `world.ts:1067`'s own comment says the floor
> is "0.155" while line 1069 ships **0.175** — the code wins over its own comment too.

**(b) The underdrawing's four tiers.** Not opt-in. Every trilayer surface.
`trilayer.ts:365–379`:

```glsl
float triT = clamp((pow(triLum(triAlbedo), 0.4545) - pow(triLum(uTriInk), 0.4545))
             / max(pow(triLum(uTriPaper), 0.4545) - pow(triLum(uTriInk), 0.4545), 1e-4), 0.0, 1.0);
float triTone = 1.0 - triT + (triNoise(vTriWorld.xz * 31.0) - 0.5) * 0.06;
float triTier = step(0.14, triTone)
              * clamp(floor((triTone - 0.14) * 6.25) + 1.0, 1.0, 4.0) * 0.25;
```

The albedo's own encoded luminance, normalised paper→ink, inverted to darkness, then cut
into **four** bins of width 0.16:

| Tier | `triTone` band | Reads as |
|---|---|---|
| 0 | < 0.14 | **bare paper — no mark at all** |
| 1 | 0.14 – 0.30 | sparse, grainy, rows lifted |
| 2 | 0.30 – 0.46 | continuous single pass |
| 3 | 0.46 – 0.62 | two passes, wider lead |
| 4 | ≥ 0.62 | three passes, hard pressure |

The `±0.03` world-space noise on the tone (`trilayer.ts:377`) is deliberate: it lands a
tier boundary **ragged** rather than as a stair-step tracing the albedo's own edges.

**Consequence for authoring albedo.** The underdrawing is derived from the paint layer's
map. A flat albedo gives a flat drawing. If a surface has no value structure in its
albedo, it has no drawing — it is a paper-coloured hole under the curtain. **Author the
albedo so that its encoded luminance spans at least two tier bands (≈0.32 of the
paper→ink range) across the form.**

### 2.3 The authored stroke tiles

Tone is not an analytic row field. It is **thousands of individual pencil strokes drawn on
a canvas and baked**, `bakeStrokeTiles()` (`trilayer.ts:94–203`).

The previous approach was procedural rows at 26/unit and it measured as **machine ruling**
— zebra bands, fingerprint swirls on the lobed crowns, a barcode chest
(`trilayer.ts:80–91`). That is the ceiling of the procedural approach, and it is the
reason this bake exists.

**Bake geometry.** 1024², four horizontal bands of 256 px, one per tier
(`trilayer.ts:96–99`). Band `k` is tier `k+1`.

**One stroke** (`trilayer.ts:115–150`): 7 short segments, a slow bow of `±0.125` rad
accumulated across the run, and a tapered width envelope
`min(1, min(t, 1-t) * 3.6 + 0.18)` — a lead laid down, pressed, and lifted. Redrawn at the
wrap offsets when it could cross a tile edge, so bands tile seamlessly in both axes.

**Per-tier authoring** (`trilayer.ts:151–192`), `ROWS = 15`:

| Tier | rowChance | passes | width lo–hi | alpha lo–hi | stroke length |
|---|---|---|---|---|---|
| 1 | 0.55 | 1 | 4.5 – 7 | 0.45 – 0.68 | 80 – 240 |
| 2 | 0.85 | 1 | 6 – 9.5 | 0.55 – 0.80 | 80 – 300 |
| 3 | 0.95 | 2 | 7 – 11 | 0.64 – 0.90 | 80 – 360 |
| 4 | 1.00 | 3 | 9 – 14 | 0.80 – 1.00 | 80 – 420 |

Per-stroke greyscale is `16 + rnd()*58` (`trilayer.ts:176`) — never pure black. Angle
variance is `±0.12` rad, **≈ ±7° around one family direction** (`trilayer.ts:175`). Rows
skip entirely at `rnd() > rowChance` — a whole row lifted off the paper
(`trilayer.ts:169`). The lead travels on, or lifts and rests, between strokes
(`trilayer.ts:187`).

**Density carries value. Clustering is the value.** Not opacity, not a grey ramp.

**Four sampler settings, each one a walked bug fix** (`trilayer.ts:196–201`):

- `colorSpace = NoColorSpace` — it is a **mask, not a colour**. An sRGB decode eats every
  half-pressure mark.
- `wrapS = RepeatWrapping`, `wrapT = ClampToEdgeWrapping` — bands wrap by shader `fract`,
  never by sampler, or tier 1 bleeds into tier 4.
- `flipY = false` — the default flip sampled tier 4 out of the near-empty tier-1 band.
- `anisotropy = 16` — at 4 the strokes smeared at grazing angles.

**Row pitch is a screen-space quantity.** `STROKE_TILE_V = 0.4` world units per band
(`trilayer.ts:93`) ÷ 15 rows = 0.0267 world units per row, which at the hero's
**161 screen px per world unit** is ≈ 4.3 CSS px of pitch (`trilayer.ts:153`). Any new
surface that changes its effective world scale must re-derive this or the drawing turns
into either a smear or a comb.

**Sampling** (`trilayer.ts:396–400`):

```glsl
vec2 triUv = vec2(triSp.x / 1.60,
                  (triTier * 4.0 - 1.0 + clamp(fract(triSp.y / 0.40), 0.004, 0.996)) * 0.25);
triMark = 1.0 - texture2D(uTriStrokes, triUv).r;
```

`STROKE_TILE_U = 1.6` world units across the stroke direction, `STROKE_TILE_V = 0.4`
along it — each band is a 4:1 slice (`trilayer.ts:92–93`).

**The mark's landing** (`trilayer.ts:401–403`):

```glsl
float triStroke = triMark * (1.0 - triFade * 0.75);
triUnder = mix(triUnder, mix(uTriPaper, uTriInk, 0.96), triStroke);
```

A full-pressure stroke lands at **96% toward ink, never at ink**. Graphite is not ink.

### 2.4 The sheet basis and the one-family rule

**THE HARD GATE: one stroke family per face, one direction per organic form. Crossing
strokes are a build failure.** `hero.check.ts:188` asserts the hero authors no
`hatch()` / `crossHatch()` at all.

Projection is chosen per material (`trilayer.ts:386–393`):

```glsl
vec3 triAn = abs(normalize(vTriWorldN));
vec2 triPp = uTriSheet > 0.5
           ? vec2(dot(vTriWorld, uTriSheetX), dot(vTriWorld, uTriSheetY))
           : (triAn.y >= max(triAn.x, triAn.z) ? vTriWorld.xz
           : (triAn.x >= triAn.z ? vTriWorld.zy : vTriWorld.xy));
vec2 triDirV = vec2(cos(uTriStrokeDir), sin(uTriStrokeDir));
vec2 triSp   = vec2(dot(triPp, triDirV), dot(triPp, vec2(-triDirV.y, triDirV.x)));
```

**Two modes, and the choice is not a preference:**

- **Sheet basis** (`stroke: { sheet: true }`). The prop projects its world position onto
  the **lens's own view plane** — the drawing's sheet. One continuous parameter space, one
  direction, for the whole prop. **Every organic form must use this.** The hero stages the
  basis at `hero.ts:1799–1806` from `HERO_AZ` / `HERO_ELEV`.
- **Dominant-axis plane** (default). A hard pick with **no cross-plane blending** — that
  is a draughtsman's box shading, adjacent regions, never a crossed second family. For
  planar, boxy things only.

The per-face flip on an organic form was the shipped **fingerprint swirl** defect
(`trilayer.ts:381–385`, `hero.ts:928–931`). If you build a curved mass without
`sheet: true`, you are rebuilding that bug.

**Family angles shipped** (`uTriStrokeDir`, radians in the projection plane):

| Form | dir | Why |
|---|---|---|
| default | 0.61 | the legacy dominant-axis family angle (`trilayer.ts:498`) |
| Tree crowns | `0.5 + (seed % 5) * 0.06` | one direction per crown, slight per-prop hand variance (`hero.ts:932`) |
| Tree trunks | `1.35 + (seed % 3) * 0.05` | near-vertical — trunks shade along their grain (`hero.ts:933`) |
| Island strata | 0.04 | near-horizontal — strata are laid beds (`hero.ts:1453`) |
| Roots | `1.15 + curl * 0.12` | one steep grain per limb (`hero.ts:1482, 1516`) |
| Rock | `0.55 + (seed % 4) * 0.07` | one direction per mass (`hero.ts:1136`) |
| Pencil | 1.5 | along the tool (`hero.ts:1178`) |
| Goblin cloth | 1.45 | near-vertical: drape falls (`world.ts:1069`) |
| Goblin skin | 0.55 | (`world.ts:1071`) |

**Rule for new work: vary the angle by ≤ ±0.2 rad between neighbouring props of the same
class.** That reads as one hand. Larger variance reads as a different draughtsman per
object.

### 2.5 Feather

`trilayer.ts:535–544`. Alpha-feathers the rim over the **local unit circle**:

```glsl
diffuseColor.a *= 1.0 - smoothstep(1.0 - max(uTriFeather, 1e-3), 1.0, length(vTriLocal.xy))
                * step(1e-4, uTriFeather);
if (diffuseColor.a < 0.01) discard;
```

The `discard` is deliberate and not a perf trick: the invisible tail must not write depth,
because the curtain pass inks depth discontinuities and a depth footprint at the geometric
circle draws a hard ring around an edge that should "simply stop being drawn." `depthWrite:
false` was rejected — the card is the ground and must still occlude what sinks below it.

**Shipped feather values:**

| Surface | feather | Site |
|---|---|---|
| Island kit default | 0.12 | `islandKit.ts:64` |
| **The hero card** | **0.012** | `hero.ts:1407` |
| Goblin contact pool | 0.22 | `world.ts:1724` |

> The hero card's 0.012 is **anti-aliasing width only**, and this is a corrected mistake.
> `hero.ts:1403–1406`: "even 0.05 left a pale halo all around the rim — grass must MEET cut
> earth." The painted rim ring in the albedo (`hero.ts:479–490`) and the strata lip carry
> the edge. **The graphite side's "stops being drawn" read comes from the rim contour's
> authored gap, never from alpha.**

### 2.6 The seam — a spatial Performance↔Prep cut

**THE SEAM IS THE COVER'S, AND THE COVER'S ONLY** (client ruling 2026-09-05). `rig.seamX`
is a module singleton shared by every trilayer material in the app, and it had two
owners: the cover stages it at `SEAM_X = 1.0` and `heroLife` drains it to
`BLANK_X = −3.4` at the handoff. Nothing put it back, and since the shader below puts
Prep **east** of the line while the film's sets live at x = 0…126, the whole world
rendered as GRAPHITE for the entire run — every ground card, flora stand, verge and rock.
The film had never shown most of its own paint.

**The film has no seam.** `Film.tsx` parks the uniform at `1e6` for the length of its own
render pass and hands it straight back, so the film's surfaces always draw with the
smoothstep shut and the cover's canvas always draws with whatever its bloom and drain
last wrote. A uniform with two owners is per-render-pass state; it is borrowed per render
pass, and neither owner can see the other's value. From the film's first frame the GLOBAL
CURTAIN alone drives painted-versus-drawn.

**`rig.depthNear` / `rig.depthFar` are borrowed on the same pass and for the same reason**
(§4.7.8): the cover stages them at its diorama's ~9 / 23 and the film's shots run to 100+
units, so under the cover's numbers every mock kit surface past 23 units washed to bare
paper. The film draws at **10 / 150**. Three uniforms, one borrow, no per-beat owner.

The hero's signature. `trilayer.ts:303–351`.

```glsl
float triSeamC = vTriWorld.x
               + (triNoise(vTriWorld.zy * 1.9 + 4.7) - 0.5) * uTriSeamWob
               + (triNoise(vTriWorld.zx * 6.3)       - 0.5) * uTriSeamWob * 0.35
               + (triNoise(vTriWorld.zx * 14.0 + 9.3)- 0.5) * uTriSeamWob * 0.14;
float triSeamF = smoothstep(uTriSeamX - uTriSeamW, uTriSeamX + uTriSeamW, triSeamC);
```

Three octaves. `SEAM_WOB = 0.75` world units at the hero (`hero.ts:53`). Parked at 0 for
the film, so the film is untouched by construction.

**The granular frontier** (`trilayer.ts:313–325`). Inside the blend band the wash breaks
into **pigment granules** — drybrush catching paper tooth — so the paint *ends in speckle*
instead of desaturating away. The noise is sampled **anisotropically, ~5:1 along the
ground brushwork's own dab angle**, so the blend commits in elongated dab-shaped patches
~0.2 world units long instead of per-pixel crumbs:

```glsl
float triSeamBand = triSeamF * (1.0 - triSeamF) * 4.0;   // exactly 0 outside the blend
vec2 triFlowP = vec2(vTriWorld.z * 0.95 - vTriWorld.x * 0.31,
                     vTriWorld.x * 0.95 + vTriWorld.z * 0.31);
float triDabN = triNoise(vec2(triFlowP.x * 26.0, triFlowP.y * 5.0) + 2.2)
              + (triNoise(vTriWorld.zx * 47.0 + 8.1) - 0.5) * 0.4;
triSeamF = clamp(triSeamF + (triDabN - 0.5) * 2.6 * triSeamBand, 0.0, 1.0);
```

**Wet-media pooling** (`trilayer.ts:341–344`) — pigment sits denser on the painted side of
the leading edge: `triPaint *= vec3(0.86, 0.85, 0.9)` at `pool * 0.5`.

**The dried edge** (`trilayer.ts:348–351`) — the tide-line where the wet frontier stopped,
riding the wobbled coordinate: `triPaint *= vec3(0.6, 0.58, 0.66)` at
`triEdge * (0.52 + 0.35 * noise)`, broken like pigment settling unevenly.

**Both terms are gated off the alive** by `triSeamPaint = 1.0 - uTriAlive`
(`trilayer.ts:341`). The comment at `trilayer.ts:333–340` records why: the seam is a
property of the **page**, and the ×0.6 dried-edge multiply was painting a tide-line across
the goblin's own cloth, taking his darkest pixel to 0.153 encoded against a gate of 0.165.

**Hero seam staging:** `SEAM_X = 1.0`, `SEAM_W = 0.2`, `SEAM_WOB = 0.75`
(`hero.ts:48–53`), applied at `hero.ts:1792–1794`. Parked at `1e6 / 0.6 / 0` for the film
(`hero.ts:1830–1832`).

`SEAM_W = 0.2` is deliberately narrow — "a worked EDGE, not a wash. A wide band read as
plain falloff" (`hero.ts:51–52`). The irregularity comes from the wobble and the granular
frontier, never from band width.

### 2.7 Page furniture, depth, and the remaining Prep channels

**Ground opt-in.** Grid and construction ghosts print **only** on surfaces that pass
`ground: true` **and** face up: `triUpF = uTriGround * smoothstep(0.55, 0.8, worldN.y)`
(`trilayer.ts:359`). The normal test alone printed the grid on crate lids
(`trilayer.ts:356–358`). Only the island card opts in (`islandKit.ts:88`).

**The battle-grid watermark.** `trilayer.ts:407–409`. Unit-cell lines,
`smoothstep(0.008, 0.022, ...)` half-width, capped at `GRID_INK = 0.04` toward ink
(`trilayer.ts:31`). **Composed AFTER the strokes** so the enforced number is the on-page
number — strokes must not launder the cap the framebuffer measurement reads back.
Asserted against a real float readback at `IslandSandbox.tsx:161–200` and by
`island.check.ts`.

**Construction ghosts.** `trilayer.ts:411–413`. A faint compass ring of radius 0.95 every
3 world units, `smoothstep(0.015, 0.05)`, at 0.1 toward ink.

**Depth language — Performance: fog-to-paper.** `trilayer.ts:329`:
`triPaint = mix(outgoingLight, uTriPaper, triFade)` where
`triFade = smoothstep(uTriNear, uTriFar, length(vViewPosition))`. **Ramps to PAPER, never
to grey.** In-material, so an island on a bare page needs no scene fog.

**Depth language — Prep: line weight.** `trilayer.ts:402`:
`triStroke *= (1.0 - triFade * 0.75)`. No fog, no shading — far strokes go fainter with
more paper show-through, exactly as a pencil renders aerial perspective.

**Depth values shipped:** film default 6 / 26 (`trilayer.ts:38–39`); hero Node default
9 / 24 (`hero.ts:1797–1798`); hero live `d * 0.95` / `d * 2.4` re-solved per resize
(`Hero.tsx:132–133`).

**Foreground silhouette.** `trilayer.ts:414–417`. Under Prep, anything nearer than
`uTriSilNear` (default 2.5, `trilayer.ts:44`) goes 92% toward ink — a shape in front of the
drawing, not a drawing.

**The alive shadow.** `trilayer.ts:427`:
`triUnder = mix(triUnder, uTriInk, (1.0 - getShadowMask()) * uTriAliveShadow)`. On the
frozen page the only shadow touching graphite belongs to what is alive. Structural, not
staged. Film default 0.3 (`trilayer.ts:65`); **hero 0.97** (`hero.ts:1825`).

**Birth.** `trilayer.ts:430`: `triUnder = mix(uTriPaper, triUnder, uTriBirth)`. The whole
Prep result rises from bare paper as the entrance writes the strokes on. 1 everywhere but
the entrance.

**The almost-touch.** `trilayer.ts:434–437`. A **≤6%** lift toward `amberLantern` following

## 3. FORM — how the island is actually built

### 3.1 Closed lathe bands, not open cylinders

`hero.ts:1430–1458`. Three `LatheGeometry` bands at 72 segments forming **one continuous
solid skirt**, each profile **overlapping the next vertically** so `roughen()` can never
open a paper gap, and **every band `DoubleSide`**.

```
earth lip   [0.996, 0.004] [1.012, -0.055] [0.99, -0.125] [0.982, -0.175]   roughen amp 0.02
stone shelf [0.998, -0.155] [0.962, -0.265] [0.93, -0.375]                  roughen amp 0.03
keel        [0.945, -0.35] [0.9, -0.52] [0.78, -0.63]
            [0.5, -0.71] [0.18, -0.77] [0, -0.79]                           roughen amp 0.05
```

All at `freq 3.1`, seeds `7 + i`, scaled `(ISLAND_RX, 1, ISLAND_RZ)` = (2.6, 1, 1.8).

**This is the third cut, and the first two failed for reasons worth carrying.**
`hero.ts:1422–1429`: the "stepped" bands were open-ended cylinders, so FrontSide culling
let the lens see **straight through the skirt** — bare paper between ribbons — and the
keel's inward taper faced away from the 33° camera entirely. The island read as hollow
ribbons under a plate.

**Two geometric rules come out of that:**

1. **Overlap every profile with the next.** `0.996 → -0.175` then `0.998 → -0.375` then
   `0.945 → -0.79`. Each band starts *above* where the previous ended.
2. **Keep the upper run of a downward taper near-vertical (≤ ~30° inward)** so a 33°
   elevation lens actually sees the stratum before the silhouette turns under
   (`hero.ts:1437–1440`). A fast taper hides a whole stratum behind its own near skirt.

**Roughening gets rougher as it goes down** (`hero.ts:1446–1448`): "the keel is the
roughest cut — a smooth keel shaded into an airbrush gradient in the walk; broken form
reads as cut earth."

### 3.2 Roughen

`pencil.ts:277–301`. Displace every vertex along its normal by deterministic 3D value
noise, then **re-derive the normals**:

```ts
const n = noise3(x*freq + seed*13.7, y*freq + seed*5.1, z*freq + seed*9.3) - 0.5;
pos.setXYZ(i, x + nor.getX(i)*n*amp*2, ...);
geom.computeVertexNormals();
```

Position-keyed noise (`pencil.ts:252–271`) so coincident seam vertices get identical
offsets — a displaced revolve never cracks open.

**This is what separates "3D primitive" from "3D that was drawn."** The re-derived normals
are the point: they break the Lambert ramp into facets the eye reads as brush decisions.

**Shipped amplitudes** (as a fraction of the form's own radius, which is how they scale):

| Form | amp | freq | Site |
|---|---|---|---|
| Crown lobes | `r * 0.10` | 3.4 | `hero.ts:974` |
| Pine cones | `r * 0.07` | 4.1 | `hero.ts:1012` |
| Rock | `r * 0.22` | 2.5 | `hero.ts:1134` |
| Strata bands | 0.02 / 0.03 / 0.05 | 3.1 | `hero.ts:1444–1449` |
| Root segments | 0.008 | 6 | `hero.ts:1479` |

Crown amplitude is capped at 0.10 for a stated reason (`hero.ts:970–972`): above it, bumps
escape the contour arcs' registration band and the drawn line stops sitting on the form.

### 3.3 The roots — what makes a limb read as grown

`hero.ts:1466–1528`. Two trailing roots, each **three segments with an accumulating curl**,
plus a rootlet at the elbow.

- Radii `[0.075, 0.05, 0.028, 0.007]`, lengths `[0.3, 0.26, 0.2]`.
- **Each segment's top radius continues the parent's end radius** — a mismatched joint read
  as broken sticks in the walk (`hero.ts:1476–1477`).
- **Joints overlap 6%**: `next.position.y = -lens[i] * 0.94` (`hero.ts:1523`).
- The curl accumulates: `seg.rotation.x = 0.2 + i * 0.12` (`hero.ts:1510`).

`hero.ts:1459–1465` records what the straight version looked like: "the P4b straight cones
read as nails hammered through the island," and later, "the two roots were the frame's only
bare smooth Lambert surfaces — table legs."

**The fix was not more geometry. It was drawn marks.** Every segment carries two drawn side
contours at `'form'` weight (`hero.ts:1486–1496`) plus two short bark streak marks at
`'faint'` (`hero.ts:1497–1509`), pushed toward the camera by a fixed local
`(0.03, 0.03, -0.07)` so each mark stays proud of its own limb's depth.

### 3.4 The drawn rim contour and its deliberate gap

`hero.ts:1548–1564`. The rim is drawn as **an open stroke, not a closed loop** — an arc
from **80° to 300°**, stepping 7°, at `y = 0.012`, jitter `±0.6%`.

**The 60° gap is the whole idea.** A drawn edge that *stops being drawn* across the
graphite side is what says "this island is only as finished as its finished part." It is
not alpha, not fog, not a fade — it is a line that ends.

`hero.ts:1557–1559` records the jitter correction: 0.035 → 0.012, because "a 1.75% radial
swing at RX 2.6 was ±7 screen px of float." **The stroke pipeline's own wobble is the
hand.** Do not add a second hand on top of it.

**Strata contours** (`hero.ts:1571–1585`) — four arcs at the section's boundaries, graphite
on the near-left skirt (10–75°), ink on the painted quadrant (96–176°). Without them "the
Lambert shade crushed earth/stone/keel into one gradient and the section read as a bowl."
The keel boundary rides **proud** of the surface (r 0.975 vs the geometry's 0.945) because
at the true radius `roughen` swallowed it.

**Section cut marks** (`hero.ts:1586–1606`) — short downward strokes every 13° from 14° to
170°, one family, ink on the painted quadrant and graphite on the drawn one. They live on
the **stone shelf's mid value** because ink dies on the caveDark keel, and their tails just
enter the dark. `'form'` weight, because `'faint'` vanished on the skirt's mid values.

### 3.5 What the eye is actually responding to

Be specific, because this is the part that gets rebuilt wrong. A form reads as **painted**
rather than as a **primitive** because of five things, in this order of importance:

1. **A broken silhouette.** `roughen()` at ≥ 7% of the form's radius, or overlapping lobes
   (`hero.ts:962–968`: five lobes for an oak crown), or stacked tiers
   (`hero.ts:1005–1009`: three for a pine). A single sphere under a stretched tile shipped
   twice and read as a smooth blob both times (`hero.ts:910–917`).
2. **An authored contour that registers ON the silhouette.** Not near it.
   `hero.ts:934–940`: arcs at **1.05×** the lobe radius painted, **1.10×** graphite (just
   proud of the roughen swing) — and they survive the solid by a **deeper camera push**,
   not by lateral distance. "The ink sat 10–40 screen px OUTSIDE the painted lobes — a
   floating line reads as a mistake."
3. **Interior separations.** Where masses meet. `hero.ts:990–998`: four short interior leaf
   arcs at mid-graphite. "They are what make a scalloped white mass read TREE, not cloud."
4. **A connected silhouette stroke, not per-part strokes.** The fir's zigzag
   (`hero.ts:1019–1051`) is **one stroke per side, tip to skirt** — "per-tier slants never
   assembled into a tree at framing; the zigzag is how a hand actually draws a fir."
5. **The silhouette stroke's radii derived from the geometry, never authored free.**
   `silR()` at `hero.ts:1026–1033` reads the tier cone profile. The free-authored version
   sat 9–16 screen px outside the mass and no scale knob could close the gap
   (`hero.ts:1021–1025`). Shipped multiplier: **0.99 painted / 1.03 graphite** — *inside*
   the tone, letting the stroke's own overshoot supply the proudness. "A drawn line INSIDE
   tone is a hand's zigzag; a line outside it is a wire tent."

**Push depths shipped** (toward `VIEW_CAM`, `hero.ts:671–675` — depth only, screen position
is preserved because the mark slides up its own view ray):

| Mark | push | Why |
|---|---|---|
| Crown contour arcs | 0.35 | at 0.15 an on-silhouette arc got half-swallowed (`hero.ts:982–984`) |
| Interior leaf arcs | 0.40 | must clear the lobe fronts (`hero.ts:992–993`) |
| Pine tier arcs | 0.30 | `hero.ts:1017` |
| Fir zigzag | 0.10 | at the silhouette the cone falls away; a deep push cost ~8 px of lateral shift (`hero.ts:1043–1045`) |
| Trunk side strokes | 0.14 | `hero.ts:949` |
| `contourArc` default | 0.15 | `hero.ts:689` |

### 3.6 Contour marks are authored in the SHOT's view plane

`hero.ts:660–675`. The hero is one fixed camera, so a drawn silhouette lives where **that
lens** sees the form's edge — exactly how a draughtsman draws what the sheet will show.

```ts
const VIEW_R   = new THREE.Vector3(Math.cos(HERO_AZ), 0, Math.sin(HERO_AZ));
const VIEW_CAM = new THREE.Vector3(Math.sin(HERO_AZ)*Math.cos(HERO_ELEV),
                                   Math.sin(HERO_ELEV),
                                  -Math.cos(HERO_AZ)*Math.cos(HERO_ELEV));
```

A wobbled pencil arc carries **6° of camera re-aim without complaint** (`hero.ts:663`) —
that is the tolerance budget for a stage whose camera moves.

### 3.7 Stroke weight is a screen-space quantity

`pencil.ts:30`: `hero 3.4`, `form 2.1`, `faint 1.1` CSS px. `pencil.ts:34–36`: below 700px
viewport width, `SCALE 0.75` and sub-segments drop 3 → 1 (same drawing, cheaper to draw;
composition never varies by device, only stroke cost).

**`'form'` at 2.1 px is the readable floor for a contour** at the hero's ~161 px/world-unit
framing. **`'faint'` (1.1 px) is for ghosts and erased passes ONLY.** `hero.ts:664–666`:
"the P4/P4b rounds shipped faint contours and both verify rounds read them as none."

Line weight is solved on the page, not in the world:
`setPencilResolution(width, height)` (`pencil.ts:65–67`) on mount and every resize
(`Hero.tsx:137`). The goblin's ink shells are the same kind of quantity:
`GOB_RIM_PX / (pxPerUnit * rootScale)` (`hero.ts:1231–1238`), `GOB_RIM_PX = 3.2`
(`world.ts:970`). A world-unit shell gave a 6.3 : 1 weight spread across breakpoints.

**The stroke wobble** (`pencil.ts:305–347`): corner overshoot `min(len*0.06, 0.05)`,
lateral amplitude `min(len*0.035, 0.024)` on two axes across the stroke, endpoints fixed,
only the interior drifts. Deterministic (`let seed` in `pencil.ts`) — a re-randomising wobble
would shimmer on reload and read as noise rather than as someone's hand. CORRECTED 2026-09-06 —
`pencil.ts:238–246` → `let seed` in `pencil.ts` (law 13: cite by symbol, not line number — the
line drifted from :238 to :247 within a day). Measured: `grep -n "let seed" src/film/pencil.ts`.
Reproduce: `grep -n "let seed" src/film/pencil.ts` from `story/story`.

### 3.8 Screen-space arithmetic — the first law of every bake

`hero.ts:323–330`. At 1440×900 the island projects ~840 px over 5.2 world units →
**~161 screen px per world unit**. A 2048 bake over that gives **394 texels/unit**, so
**1 texel ≈ 0.41 screen px**.

**Therefore a brush dab must be authored ≥ 25 texels long (~10 screen px) and ≥ 5 texels
wide (~2 screen px) to read at framing.** The 1024 bake's 9–27 px dabs at 0.28 alpha
between near-identical greens were "~2 effective screen px of nothing."

The same law re-derived for foliage (`hero.ts:562–567`): a crown lobe is ~0.3 world units
(~48 screen px radius) and its sphere UV wraps the whole tile around it, so at 512 one
texel ≈ 0.5–1 screen px. **A leaf cluster must be ≥ 40 texels (~25 screen px).** The old
256 tile's 14–36 px blotches projected as out-of-focus noise.

**Do this arithmetic before authoring any new bake. Write the result in a comment.**

### 4.7 Why your blue looks brown — the rig's colour transfer, and how to author against it

**[REVISED 2026-09-05 — the key is now a per-chapter-family colour. Every number in this
section was re-measured under the film's own rig and the new keys. If you have the old
§4.7 in your head: the pre-compensation table is now a no-op for ext-day, and the
`#C0C0C0` ceiling is gone.]**

**The short version.** A token is not what you see. The rig multiplies every authored
albedo by a **per-channel gain** before it reaches the page, and *which* gain depends on
two things you have to know before you author anything: **which rig you are under**, and
**which chapter family the surface lives in**.

- **The cover** (`stages/rigs.ts`, and every `?mock=` sheet) is lit by `keyWarm #FFEACC`
  over a `skyDay` hemisphere at `HEMI_I 0.8`. Its gain is warm on every up-facing and
  key-facing surface. `snowShadow #AEB5C0` is authored at R−B = −18 and lands on an
  up-facing form at R−B = **−2**; `snow #F2F2EC` (R−B = +6) lands at **+22**.
- **The film** (`Film.tsx`) is **not** lit by that rig. Its fill is `fillSky #CDD9E8`
  over `fillGround #8A7458` at `HEMI_I 1.45` — cooler, and nearly twice as strong — and
  its key colour is a per-chapter-family token (§4.2, `keyDay` / `keyWarm` / `keyNight`).
  On the **ext-day** family the gain is now **flat**: an up-facing white lands at
  R−B = −0.0007 in the linear mix domain, which is 0/255 encoded.

Nothing in the palette says any of this, which is why it kept being read as a
surface-author error. It is not. It is the rig, and it is arithmetic.

Measured by `?mock=transfer` (`src/film/mock/transfer.ts`) — an off-canvas
`FloatType` / `NoColorSpace` readback, **linear mix domain, never sRGB bytes** (§10.2; a
previous round shipped a calibration bug by measuring in bytes). The probe now takes the
rig it is asked for: `await window.__transfer()` for the cover,
`window.__transfer('extDay' | 'extNight' | 'interior')` for the film's families. 440
samples, 22 tokens × 5 orientations × 4 rigs, with the closed-form model agreeing with
the framebuffer to **7 × 10⁻⁷** worst residual across every row.

#### 4.7.1 The transfer is a diagonal gain — that is the whole mechanism

Unchanged, and it is why everything else in this section is arithmetic rather than
opinion. Lambert has no cross-channel term. For a trilayer surface with world normal **n**:

```
screen_linear = albedo_linear ⊙ G(n)          (⊙ = per channel)

G(n) = [ mix(ground_lin, sky_lin, 0.5·n.y + 0.5) · HEMI_I
       + key_lin · KEY_I · max(0, n·k) ] / π
```

**k** = the key's axis. The `/π` is Lambert's `BRDF_Lambert`; the intensities carry it by
design (`rigs.ts:33-34`). `KEY_I = 2.2` in **every** rig and every family — §5.5 pins the
key's intensity, so a family that wants a demoted key takes it out of the colour's own
luminance instead (`keyNight` sits at 0.51× `keyDay`'s luma).

**What changed is only the two inputs**: `HEMI_I` and the sky/ground pair (cover 0.8 ·
`skyDay`/`earthTrack`, film 1.45 · `fillSky`/`fillGround`), and `key_lin`, which is now
per family. The key still outweighs the fill, but on the film's ext-day family the two
are *tuned against each other* rather than compounding: the fill's coolness and the key's
warmth cancel on an up-facing surface by construction.

#### 4.7.2 THE MEASURED TRANSFER — gain vectors

Four rigs ship. Read the one your surface is actually under.

Orientations: **KEY** = normal on the key axis · **UP** = `(0,1,0)`, the massif top ·
**VERT** = `(0,0,1)` · **SHADE** = `(-1,0,0)` · **LEE** = the key axis negated.

**The film's key axis is not a fixed sun.** `Film.tsx` re-stages it every frame from the
lens: `keyPos = look + view·10 + up·14 + right·(−9)`, so on an up-facing surface

```
n·k = (10·sin E + 14) / sqrt(377 + 280·sin E)          E = the camera's elevation
```

which runs **0.721** at the horizon, **0.78** at the film's median exterior beat, and
**0.936** straight down at S7/S8. The film rows below are quoted at **n·k = 0.78**; §4.7.7
gives the spread across the whole range, and it is small.

#### 4.7.4 THE INVERSE — what to author for a wanted on-screen reading

**Unchanged. This is the rule, and it survives the ruling intact.** The transfer is
diagonal, so it inverts channel by channel — no matrix, no solve:

```
albedo_linear = target_screen_linear ⊘ G(n)
authored_hex  = sRGB_encode( albedo_linear )
```

**Valid range.** Exactly one condition: `albedo_linear ≤ 1` in every channel, i.e.

```
target_screen_linear_c  ≤  G_c(n)      for c ∈ {R, G, B}
```

`G(n)` **is** the on-screen value of a pure-white albedo. The rig's own colour at that
orientation is a hard ceiling: an albedo can only subtract from it. There is no authored
value that raises a channel past it.

**Pre-compensation, as a recipe.** To keep a token's authored *hue* while landing at the
brightness the rig already gives it (so nothing else in the frame moves):

```
k  = lum(albedo ⊙ G) / lum(albedo)          # the scalar the rig would have applied
a' = albedo · k ⊘ G                          # the token to author instead
```

with `lum = 0.2126 R + 0.7152 G + 0.0722 B` on **linear** values.

**Where it breaks down, and where it no longer has to.** Coolness is capped by the blue
channel. On the cover's rig blue is the smallest component of `G` on every lit
orientation, which is what fixed the old ceiling. On the film's **ext-day** family the
three components are equal to 0.16 %, so there is no cap worth naming at UP. The ceiling
per rig, as the brightest **neutral-or-cool** value reachable on screen:

#### 4.7.8 The two other terms in the chain

Both push **toward paper `#F7F5F0` (R−B +7)**. Neither is token-dependent; both are
excluded from the tables above. **Under ext-day this is now the largest remaining source
of warmth in a lit frame**, which makes it worth more attention than it used to get.

- **Edge wear** (`trilayer.ts`, `uTriWear`; the film scales the mock values by
  `FILM_WEAR = 0.55`, `sets/kit.ts`):
  `mix(lit, paper, pow(1 − |N·V|, 2.5) · wear)`. A **view**-angle term, not a light term —
  it is why a glancing rim on a massif measures warmer and brighter than §4.7.4's ceiling.
- **Fog-to-paper** (`uTriNear` / `uTriFar`): `mix(lit, paper, smoothstep(near, far, dist))`.
  Distance dissolves into the page (§4.6), and the page is warm. **The whole film runs
  this at 10 / 150** — the film's own scale, read off its `FogExp2(0.0085)` — borrowed for
  the length of the film's render pass alongside the seam (§2.6). It used to be staged
  only for materials that happened to pass through `sets/kit.ts`, which left every mock
  kit surface reading the cover's ~9 / 23 and washing to bare paper past 23 units: walked
  at t33.5, the S3 island's standing backdrop sheet rendered as a blank white slab behind
  the theatre. Same singleton, same two owners, same fix.

The amber flame practicals (`PointLight`, distance 8, decay 2, §5.1) are **local** warm
terms inside 8 world units of a fire, and are zeroed in the measurement. Near a fire, add
them — and in S1 and S2 that is the whole point: the night key is neutral precisely so the
fire's pool is the only warm light in the frame.

### 5.3 The alive rule — the one thing that must not change

**On the frozen page, the only shadow belongs to what is alive.**

This is **structural, not staged** (`rigs.ts:14–20`). Three mechanisms:

1. `markAlive()` (`curtain.ts:65–98`) makes the **permanent** casters: enables the mask
   layer, sets `castShadow = true`, sets `userData.alive = true`, and flips the
   **material's** `userData.alive` uniform to 1 so the surface keeps its paint whatever the
   curtain or seam does.
2. `markCaster()` (`rigs.ts:101–109`) registers the painted world's casters — **rig-owned,
   per-rig, not module-global** (a module registry retained meshes forever under HMR and
   let a discarded render drive `castShadow` on a live one).
3. `update()` (`rigs.ts:156–157`) releases the world's casters at the fully-drawn page:
   `mesh.castShadow = painted || mesh.userData.alive === true`. **An alive mesh wins in
   every state. Nothing un-marks the alive** — `rigs.check.ts:69–72` asserts no
   `castShadow = false` and no unmark API exists anywhere in the codebase.

**The key is the only shadow-casting light in either rig.**

`markCaster` skips mask-only geometry (`rigs.ts:104`): a `reveal()` shell is a silhouette
for the curtain mask, not a prop. The aliveness test uses the dedicated `userData.alive`
flag, **never the mask layer**, because shells live on layer 1 and are not alive.

**Which props may register.** `hero.ts:203–212`: **only props whose full shadow throw stays
clear of the seam band.** `shadowReachX(x, height)` (`hero.ts:215–219`) computes the tip
reach under the restaged key, and `hero.check.ts` asserts the math. The hero registers
exactly two: the oak at `(-0.95, -1.0)` h 1.25, the pine at `(-2.2, 0.8)` h 1.6
(`hero.ts:1779–1780`).

**Everything else grounds through a painted contact blob in the albedo** — a miniature
painter's craft, not a lighting hack.

### 5.4 Contact and cast shadow treatment

**Painted contact blobs** (`hero.ts:529–552`). A radial gradient of `caveDark` from alpha
`a` to 0, baked into the ground albedo:

```
lantern post   r 48  a 0.30      signpost      r 40  a 0.28
mushrooms ×3   r 18–20 a 0.26    support stone r 22  a 0.24
painted rock   r 26  a 0.24      painted oak   r 58  a 0.26
painted pine   r 50  a 0.26      the goblin    r 24  a 0.40
```

**Graphite props get none.** `hero.ts:530`: "a drawing casts nothing, and grounding one
would lie."

The goblin's blob is darker (0.40) and tighter (24) than everything else
(`hero.ts:549–552`) so that the painted blob, the trilayer contact pool and the boots "all
agree on where he touches instead of three softnesses fighting."

**The island's page drop shadow** (`islandKit.ts:33–58`). A dedicated shader, not a
trilayer:

```glsl
float cSeam = max(uCurtain, smoothstep(uSeamX - uSeamW, uSeamX + uSeamW, vWorld.x));
float a = (1.0 - smoothstep(0.62, 1.0, r)) * 0.24 * (1.0 - cSeam);
```

A **plateau falloff**: near-full strength holds out past the card's rim (the card sits at
shadow-local r ≈ 0.8), then exhales to nothing at the shadow's edge — so a legible soft
band actually escapes the silhouette instead of hiding under the opaque card. It reads the
seam **by identity** (`islandKit.ts:103–104`), so the island is only as real as its
finished part. `depthWrite: false`, `renderOrder = -1`.

Kit: scale 1.25×, offset `(-rx*0.07, -0.06, rz*0.06)`. **Hero: scale 1.32×, y −0.98**
(`hero.ts:1418–1419`) — the keel drips to y −0.79, so the page sits below the drip point.

**The crossing shadow — the hero's signature.** `rig.aliveShadow = 0.97` (`hero.ts:1825`),
against the film's 0.3. His silhouette appears twice on the page: once in colour, once as a
drawn shadow.

## 6. CAMERA

### 6.1 The lens

`HERO_FOV = 32`, **fixed** (`hero.ts:54`). **No FOV tween exists here or ever will.**
`hero.check.ts:179` pins the constant; `hero.check.ts:184–185` asserts there is exactly one
`.fov =` write in the whole shell and that it is `cam.fov = HERO_FOV`.

> **CODE WINS — the film's framing contract does not apply to the hero.**
> `framing.ts` holds the film's authored 42° horizontal field and a pull-back capped at
> 2.2 (sized to the tavern box). `hero.ts:221–230` **consciously supersedes it**: "the hero
> is a poster on an open page: its lens is a fixed 32° tele and the comp REBALANCES per
> breakpoint." Both are live. The hero's is the quality bar.

### 6.2 Elevation and azimuth

`HERO_ELEV = 33°` (`hero.ts:55`). `HERO_AZ = +18°`, and `HERO_AZ_PORTRAIT = +18°`
(`hero.ts:68, 88`).

> **CODE WINS — the azimuth sign.** `hero-design.md §3` specifies **−18°**. The shipped
> value is **+18°**, and `hero.ts:56–67` records why the doc's two requirements are
> mutually exclusive under the shipped architecture: the seam is a world-**x** plane shared
> by identity across the trilayer, the island drop shadow and the rigs, so its on-screen
> tilt is set by the camera azimuth alone. At −18° the diagonal **flips** — graphite lands
> upper-left, and the first build shipped −18° and the verify round measured exactly that.
> §2's diagonal (graphite lower-left) is the outcome the doc argues for; +18° delivers it.

> **CODE WINS — the portrait azimuth.** The shipped value was 24° and moved to 18° on a
> live sweep (`hero.ts:69–88`), because the face-plane gate G6 read 35.1 / 35.9 / 37.0
> portrait against 47.5 landscape — three fails. The sweep: 24° → three fails; 21° → two;
> 19° → passes on the boundary; **18° → 41.0 / 41.8 / 42.9 / 47.5, centred in the 40–48°
> band.** The camera moved because the camera was what was wrong; the figure was not
> rotated (§3.4 forbids it).

**The axis consequence, and it is the one everyone gets backwards:** the camera sits on the
**−z hemisphere**, which puts world **+x on SCREEN LEFT** (`hero.ts:25–31`). Painted is
`x < SEAM_X`; graphite is `x > SEAM_X`; **graphite owns screen-left.**
`hero.check.ts:67` asserts `f.position.z < 0`.

### 6.3 The framing solve

`heroFraming(width, height)` (`hero.ts:231–277`). Not a formula — **a fitted solve**, six
iterations:

1. Seed the distance from the rim ellipse's analytic projected half-width.
2. **Project the actual rim** — 48 points around the `(ISLAND_RX, ISLAND_RZ)` ellipse —
   measure its screen extent, and scale `d` by `measured / target`.
3. **Walk the look target** (camera rides along) until the island origin projects to
   exactly `(cx, cy)`.

`hero.ts:226–229` records why: "the P4 verify round measured the formula 3–5vw and 5vh off
its own comments."

**The authored comp** (`hero.ts:93–110`):

| | Landscape | Portrait |
|---|---|---|
| Island share of viewport width | 0.58 | 0.92 |
| Centre x | 0.46 | 0.50 |
| Centre y | 0.54 | 0.56 |
| Max island px | 1040 | — |

Centre x is shifted left so **the goblin lands the left third-line and the lantern the
right** — hero §2's diagonal pair, pinned by projection asserts in `hero.check.ts`.

> **CODE WINS — portrait centre y.** The hero doc specifies 48vh. Shipped is 0.56 plus an
> aspect-aware solve (`hero.ts:104–109, 145–160`): at 48vh "the brand block lands on the
> island's far grass at tablet portrait and the bottom 40% of the frame is empty paper."

> **CODE WINS — the pine tip extent.** `hero.ts:129–134`: "the old analytic 0.336 was ~60px
> short at 768×917." The shipped `PINE_TIP = 0.45` is **measured at the portrait lens, not
> modelled**.

**Three measured render-extent constants** the solve needs because geometry is not the
silhouette:

- `RIM_OVERHANG = 1.045` (`hero.ts:112–118`) — the island **renders** ~4.5% wider than its
  rim solve, from the strata lip (r 1.012), roughen bumps, and stroke overshoot. Measured
  live at 768×895: 94vw rendered against a 92vw rim solve.
- `BELOW_FRAC = { landscape 0.43, portrait 0.465 }` (`hero.ts:120–128`) — the rendered
  extent **below** centre (strata keel plus trailing roots), measured per aspect because
  the portrait lens projects the roots deeper.
- `PINE_TIP = 0.45` — the tallest rendered content, drawn tip stroke included.

### 6.4 The composition rules that come out of it

1. **Nothing touches the viewport edge.** Absolute. Page margin is
   `clamp(18px, 2.6vw, 36px)` (`hero.ts:142`) and the solve honours it **against rendered
   extent, not geometry** — that is what `RIM_OVERHANG` and `BELOW_FRAC` are for.
2. **Frame against measured extents, never against the geometry's bounding box.** Three
   separate constants exist because three separate walks found the box lying.
3. **The type field and the world are solved against each other.** `hero.ts:152–160`: the
   brand block stacks in px from 9vh while the island's extents are width-driven, so the
   island **sinks** until the pine tip clears the type with air, and **shrinks** when the
   window is too short to also keep the keel and roots off the bottom margin.
4. **Wide desktops rebalance both knobs.** `hero.ts:95–101, 176–181`: the px cap rises to
   1040 **and** the centre eases toward frame middle as the cap bites, so leftover paper
   splits evenly. Measured: dead paper right of the island 29.7% → 24.3%. 1440×900 keeps
   the authored comp untouched by construction.
5. **The subject must clear a measured size floor.** `solveGoblinScale` (`hero.ts:1259–1291`)
   projects the figure's actual fill meshes and solves the root scale so the figure is
   **≥ 58 CSS px** tall, capped at **1.35×** desktop. `hero.ts:1253–1258` explains the
   58: gate G7's floor is 52, "solving to exactly 52 makes the gate a coin-flip on the last
   float (it landed at 51.9997 and failed), and 52 px is the size the walk called 'an
   unreadable dark smudge with one yellow dot' in the first place."
6. **Prop berths are solved against what they silhouette against, not against a plan.**
   `hero.ts:191–201`: the lantern moved to the near rim because "a lit lamp against a dark
   canopy is a dark lamp." `hero.ts:1682–1687`: the graphite pine moved a lateral
   half-stride because it sat down the +18° view ray from the graphite oak and vanished
   behind it.

> **CODE WINS — the goblin's staged height.** Hero §2 stages him at **0.62** world units.
> Shipped `GOB_SCALE = 0.75` (`hero.ts:50`), with the reasoning at `hero.ts:1318–1327`: at
> 0.62 he measured ~80px at 1440 and a dark speck at 500, and no contour weight, cloak
> value or crisped shadow made "a goblin with a pencil" read at first glance. 0.75 keeps
> the locked design and proportions — a uniform scale, nothing redrawn.

## 7. MOTION

### 7.1 Two clocks, and they never mix

**The world clock.** `Hero.tsx:151–158`. Accumulates `min(delta, 0.1)` — a woken
`'never'`/`'demand'` loop hands back whole seconds. Drives `rigs.update(t)`, the flicker,
the dolly breath, the moth, motes, blink and scritch. A freeze stills every term
(`motion.ts:82`).

**The scroll playhead.** `gearing.preScrub` (`Hero.tsx:69–75`). Drives the handoff **and**
the cover teardown from the **same eased value**, so the cover can never be torn down
mid-handoff. `Hero.tsx:207–211` records the bug that forced this: raw `window.scrollY`
crosses the carve ~0.8s before the eased playhead under the expo scrub, cutting all of
Phase B on a fast first scroll.

### 7.2 Ease lanes

`motion.ts:47–69`. Four lanes, and they do not cross:

- **Scrub** — `'none'`. Everything mapped 1:1 to scroll.
- **Settle** — camera beats, reveals, rig moves, UI, lettering. `arrive: power2.out`,
  `move: power2.inOut`, `exit: power2.in`, `heavy: power3.out`, `snap: power4.out`.
  **Never bounce / back / elastic.**
- **Puppet** — in-world prop and character acting ONLY. `pop: back.out`,
  `organic: sine.inOut`, `glide: sine.out`, `drop: bounce.out`. Never UI, camera, type,
  margin or CTA.

**Two timing rules the scale enforces** (`motion.ts:5–9`, asserted by `motion.check.ts`):
no durationed UI motion under 100ms except `T_FLICK` acknowledgments; **nothing between
0.25s and 0.4s** — the gap keeps UI-speed and world-speed legibly different.

### 7.3 The entrance

`heroLife.ts:44–53`, in seconds from first paint:

| Beat | at | dur |
|---|---|---|
| grid ghost + margin ticks | 0.25 | 0.20 |
| **~78 strokes write themselves on** | 0.45 | 1.2 min / 4.0 max, stagger 3 |
| lantern ignites | 1.65 | 0.35 |
| paint blooms | 1.75 | 0.80 |
| type settles | 2.40 | wordmark 0.48, tagline 0.36 (lead 0.12), meta 0.30, rise 0.32 |
| **settled by** | **3.20** | asserted, not aspired |

**Light leads.** Ignition at 1.65 precedes bloom at 1.75. Pinned by the check.

**The strokes ARE the loader. No spinner exists.** `heroLife.ts:352–392`: pacing is elastic
against `document.fonts.ready` — at 85% a not-ready page slows the hand to a crawl
(×0.18 timeScale, strokes keep drawing); at 100% it rests the pencil until ready, capped at
4s. A true stall over 3s pencils a margin note on.

**One lever runs the whole paint story: `rig.seamX`** (`heroLife.ts:23–26`). The entrance
blooms it `BLANK_X (-3.4)` → `SEAM_X (1.0)`, the handoff drains it back, and a backward
scrub **re-ignites lantern-first by construction** — the lantern sits nearest the painted
rim, so the returning frontier reaches it first. No second mechanism, no ordering table.

Prop visibility toggles are solved **analytically** against the bloom's `power2.out`
(`heroLife.ts:311–315`): `bloomCross(x) = bloom.at + (1 - sqrt(1 - q)) * bloom.dur`.

**Any input completes the entrance instantly** (`heroLife.ts:471–480`), and it must use
`progress(1)` with events ON — suppressing events also suppressed the stroke tween's
`onUpdate` and left the underdrawing at `instanceCount 0`.

**Reduced motion is an honest still.** `heroLife.ts:486–494`: the entrance becomes a
≤0.4s crossfade to the settled frame, and the still is `REST` — the **same pose table**
`stageGoblin` staged from and `posterBake` prints (`heroLife.ts:209–218`,
`posterBake.ts:40–43`). One table, three readers, so the frame cannot fork.

### 7.5 The handoff

`heroLife.ts:56–65`, in pre-film t (the slice is `HERO_T` long):

| Beat | at |
|---|---|

| his shadow lifts off the drawing | 0.10, dur 0.25 |

Recede is 6% dolly-back, composed onto the same view axis as the breath
(`Hero.tsx:167–169`).

The drain is **linear** so crossings are exact (`heroLife.ts:548`), and prop toggles are
solved from the drain, not tabled (`heroLife.ts:549–551`).

unwritten — so a backward scrub restored blankness instead of re-writing the brand.

### 7.6 The timing signatures that make it feel authored

1. **Light leads paint.** Always. Ignition precedes bloom by 0.10s.
2. **One lever, both directions.** Reverse is not authored; it falls out of the geometry.
3. **The loader is the content.** Strokes drawing *are* the wait. No spinner exists
   anywhere.
4. **The fastest move is reserved.** 120ms is the head snap and nothing else.
5. **Overlap, don't queue.** The tagline starts 0.12s **before** the wordmark finishes.
6. **Idle life has a reason to stop.** After 4s of cursor stillness he loses interest and
   goes back to work — the ornament has a motivation, not a loop.
7. **Every ornament stills exactly at the lit pose under PRM.** Not damped. Still.

## 9. WHAT MAKES SOMETHING FAIL THIS BIBLE

Each of these has a shipped defect behind it. They are recognition signatures, not taste.

**1. A smooth Lambert mass.** A sphere, cone or cylinder with no `roughen()`, no poster and
no contour. It shades into an airbrush gradient. *Seen:* the two roots — "the frame's only
bare smooth Lambert surfaces — table legs" (`hero.ts:1461–1463`); the keel before it was
roughened (`hero.ts:1446–1448`).
**Test:** does the silhouette break? does the Lambert ramp cross a value step?

**2. Ruled analytic stripes.** Procedural rows. *Seen:* the 26-rows/unit field measured as
**zebra bands, fingerprint swirls on lobed crowns, and a barcode chest**
(`trilayer.ts:80–91`). That is why `bakeStrokeTiles` exists.
**Test:** do rows skip? do strokes taper at both ends? is the spacing irregular?

**3. Gradient washes.** A soft radial or linear ramp standing in for form. *Seen:* the
first ground bake's "random soft ellipses" read as **airbrush clouds** and their accidental
radial spread as **a concave ring** (`hero.ts:341–345`).
**Test:** is the mass clustered? does the light have a direction? are there ≥3 separated
value tiers?

**4. Crossing strokes.** Two families over one region. **This is an absolute gate.**
`hero.check.ts:188` fails the build on any `hatch()`/`crossHatch()` in the hero. On an
organic form, omitting `sheet: true` produces this automatically via the per-face flip
(`trilayer.ts:381–385`).
**Test:** one family direction per face; one direction for the whole organic prop.

**5. A default primitive.** `SphereGeometry` at 32×16 with a flat colour. *Seen:*
`hero.ts:910–917` — a single sphere/cone under a stretched foliage tile "shipped twice as
a smooth blob," and its `inkEdges` pass gave "facet noise plus a pole fan instead of a
silhouette."
**Test:** is the mass built from overlapping lobes or stacked tiers? are its contours
authored, or extracted from where the mesh happens to bend?

**6. A surface with no committed tiers.** A form whose whole value range lands in one bin.
*Seen, measured:* the goblin's cloak scanned `62,62,62,62,62,63,63,63,64,64,64,65,65`
across the bell (`world.ts:1055–1057`) — the shipped "smooth Lambert, no tiers, does not
share the world's material language" finding.
**Test:** a 26-sample scan across the widest span must show **≥ 4 distinct plateaus with
a step ≥ 2/255 at each boundary.** If the encoded range is under 60/255, no step count
saves it — fix the albedo or the lighting.

**7. An object that is assembled rather than formed.** The named complaint: "a robot made
out of tins and shapes." The signature is **visible joins**: a mismatched radius at a
segment boundary reads as **broken sticks** (`hero.ts:1476–1477`); non-overlapping lathe
profiles let `roughen` open **paper gaps** (`hero.ts:1426–1428`); open-ended cylinders let
the lens see **straight through** a skirt.
**Test:** does every joint continue its parent's end radius? do adjacent profiles overlap
vertically? is anything `FrontSide` that the lens can see the inside of? Does the
silhouette read as one form, or as a parts list?

**8. A floating contour.** A drawn line that does not register on the mass. *Seen:* ink 10–40
screen px outside the painted lobes (`hero.ts:934–938`); the fir's authored radii 9–16 px
outside the tone (`hero.ts:1021–1025`); the rim line ±7 px off the paint edge
(`hero.ts:1557–1559`).
**Test:** contour radius is 0.99–1.10× the form's own radius, derived from the geometry.
It wins depth by a **camera push**, never by lateral distance.

**9. A `'faint'` contour doing a `'form'` job.** *Seen:* "the P4/P4b rounds shipped faint
contours and both verify rounds read them as none" (`hero.ts:664–666`); `'faint'` marks
vanished on the skirt's mid values (`hero.ts:1603`).
**Test:** `'faint'` (1.1px) is for ghosts and erased passes only.

**10. A bake authored without screen-space arithmetic.** *Seen:* 9–27px dabs at 0.28 alpha
= "~2 effective screen px of nothing" (`hero.ts:326–330`); a 256 foliage tile's blotches
"projected as out-of-focus noise" (`hero.ts:564–566`).
**Test:** the comment above the bake states px/world-unit, texels/unit, and the minimum
authored feature size in texels.

**11. Grounding a drawing.** A contact blob under a graphite-side prop. **A drawing casts
nothing, and grounding one would lie** (`hero.ts:530`).

**12. A second hand on top of the stroke pipeline's.** Adding jitter to a mark that
`strokes()` already wobbles. *Seen:* rim jitter 0.035 → 0.012 (`hero.ts:1557–1559`).

**13. A value that only exists as a hex literal.** Every colour is a `palette.ts` token or
a `mixHex` of two tokens. `hero.check.ts:190` and `:265` enforce this.

**14. Anything judged under a tone curve.** See §1.2.

## 10. HOW TO CHECK

### 10.1 What a script measures

`npm run check` runs **thirteen** Node checks under `--experimental-strip-types`
(`package.json`). The ones that bind this document:

| Check | What it proves |
|---|---|
| `island.check.ts` | trilayer uniforms shared **by identity**; fog off; the fog-to-paper line is `mix(outgoingLight, uTriPaper, triFade)`; line-weight falloff is `1 - triFade*0.75`; silhouette threshold is rig-side; the final mix is `mix(triPaint, triUnder, triC)`; the drop shadow reads the seam by identity |
| `hero.check.ts` | **no hatching**; no re-inlined paper/ink; 33° elevation at every breakpoint; camera on −z; comp centres within 0.01 of authored; one `.fov` write and it is the constant; the seam staged by identity; ≥10 alive meshes from frame one; the key at ~35°; warm sources on the painted side; caster throws clear the seam; the parked rig restores film defaults |
| `rigs.check.ts` | amber is the locked hue and the only glow; **no `castShadow = false` anywhere**; **no unmark API exists**; PRM stills the flame at exactly the lit pose; sky/ground/flat lights are palette tokens |
| `motion.check.ts` | the duration scale, the 0.25–0.4s gap, the ease lanes, no re-typed literals at wired call sites |
| `hero-life.check.ts` | the entrance schedule, light-leads-paint, the stroke count band, the handoff slice |
| `gob.check.ts` | one pose table (G10); every contoured node alive (G12); the figure scale and rim solves |

**Both must pass before any surface work is called done:**

```
npm run build   # tsc --noEmit && vite build
npm run check
```

### 10.2 What a framebuffer measures

Two harnesses exist. **Use them instead of squinting at screenshots.**

**`window.__gob(width, height, { ss, curtain, assert })`** — `gobMeasure.ts`, DEV only,
installed at `Hero.tsx:237–242`. Renders the live scene through the authored framing into
an offscreen **FloatType / NoColorSpace** target and reads pixels back. Gates P1–P8.

Its method is the part to reuse: **four draws, no colour classification**
(`gobMeasure.ts:48–63`). Deciding "these are his pixels" by colour would be circular, so
regions come from the scene graph — a mask-layer draw with a white override for exact
coverage, the frame as it ships, the frame with the subject hidden (isolating the ground
darkening it causes), and the frame with the trees hidden (giving exact crown masks). Only
small sub-rects are read back.

**Build any new acceptance gate this way.** Float target, scene-graph isolation, both
domains reported, thresholds evaluated in `_enc`.

**The island sandbox** (`?sandbox=island`, `IslandSandbox.tsx:161–200`) — the grid-ink
measurement. Renders Prep twice, grid on and grid off, into a float target, and recovers
the shader's own **linear mix factor** per pixel: `g = (lumOff - lumOn) / (lumOff - lumInk)`.
That is the exact unit `GRID_INK` caps — like-for-like, no sRGB laundering. `:163–165`
records why byte readback is not acceptable at this base tone: it jitters ±1.2% per byte
and swamps a 4% signal.

**The QA handles.** `window.__hero` (`Hero.tsx:79`), `window.__strokeTiles`
(`trilayer.ts:206–208`), `window.__bakePoster()` (`posterBake.ts:30`). Scrub uniforms and
read the staging out of the scene.

**A poster-bake trap worth knowing** (`posterBake.ts:65–71`): `setPencilResolution` and the
rim solve size lines in **resolution** pixels. Handing them the supersampled buffer size
shipped every stroke at half the authored weight — the poster's rim landed at ~1.6 CSS px
against `GOB_RIM_PX` 3.2. Pass the **logical** size.

### 10.3 What only a human can look at

No script decides any of these. They are the walk.

1. **Does it read as painted, or as lit primitives?** Nothing measures this. The proxies in
   §9 catch most cases; the eye catches the rest.
2. **Can a stranger name the object?** The literal bar the build has used repeatedly —
   "completely illegible as a chest" (`hero.ts:1098–1099`), "the pine must be NAMEABLE"
   (`hero.ts:1682`), "a goblin with a pencil" reading at first glance.
3. **Do the strokes read as one hand?** Family angle variance across neighbouring props,
   wobble amplitude, whether one prop looks like a different draughtsman.
4. **Does the drawn half look unfinished on purpose, or just unfinished?** The rim gap, the
   erased-and-redrawn arc, the measure ticks, the half-contoured tree — these must read as
   *work in progress*, not as missing assets.
5. **Does light lead?** The ignition-before-bloom order is checked; whether it *feels* like
   light leading is not.
6. **Is anything competing with the subject for value or chroma?** P1 measures the cloak
   against the crowns only. A new dark prop can pass every gate and still steal the frame.
7. **Does the reduced-motion still hold up as a frame?** It must be a poster, not a paused
   animation.
8. **Does it hold 60fps on the target device?** The subject is on screen for nearly the
   whole film.

**And the walk that supersedes all of the above:** open it at 390×844, 768×1024, 1440×900
and 1920×1080, in Chrome, with the console open, and look at it. Every superseded number in
this document — the azimuth, the goblin's scale, the shadow strength, the shadow radius,
the pine tip, the lantern's berth, the pool's hue — was found that way and then measured,
never the other way round.

## 11. THE WORLD — every surface in the film

The client's instruction, verbatim, is this part's whole brief:

> *"now its time for the terrain items (everything present in the story — cliff, adventurers,
> attacks thrown at goblin — till the end — every surface and sky and forest and everything has
> to be repainted and rebuilt. We have to completely reimagine the world structure texture and
> pallete to meet our hero's brushing and sketching skills. It should be natural throughout the
> story."*

Read exactly: **every** surface is rebuilt, not adjusted — structure, texture and palette are all
open. The hero's brushwork and its drawn black-and-white are the standard to **meet**, not to
restyle. And *natural throughout* is a hard requirement: the world must read as one continuous
place a single hand made, not as eight unrelated sets.

This part reconciles the two design passes —
`docs/build/direction/WORLD-SURFACES.md` (places and surfaces) and
`docs/build/direction/CAST-AND-EFFECTS.md` (everything alive or transient) — into **one table
that is the build's working document**, plus the continuity that makes it one world. Where the
two passes disagreed, §11.4 names the disagreement and decides it. Nothing here is an option.

§§1–10 above are unchanged and still win on the transfer, the trilayer, the two quantizers, the
sheet basis, the form rules and the failure signatures. §8's class table is the *hero's* census;
**§11.2 supersedes it for the film body**, row for row, and marks where a row moved.

---

### 11.1 The one sentence

**The hero island is not a sample of this world — it is a slice of it, and every other place in
the film is the same island at a different size, dressed for a different job.**

Twelve islands, one skirt formula, one ground painting, one stroke-angle ladder, one rim-contour
grammar with its deliberate gap, one wear vocabulary, one backdrop class. The film changes
weather, scale and dressing. It never changes hands.

### 11.3 The drawn half is computable — author against it

The underdrawing's tier is a deterministic function of the albedo's encoded luminance
(`trilayer.ts:365–379`), so **every "what does this look like under the curtain" question in
§11.2 was answered by arithmetic before anything was built**, and every adjacency conflict was
found the same way:

```
triT    = (enc(lum(albedo)) − 0.1526) / 0.8072
triTone = 1 − triT                    (± a ±0.03 world-space noise that lands boundaries ragged)
tier    = triTone < 0.14 ? 0 : clamp(floor((triTone − 0.14) × 6.25) + 1, 1, 4)
```

| tier | `triTone` | reads as |
|---|---|---|
| 0 | < 0.14 | **bare paper — no mark at all** |
| 1 | 0.14–0.30 | sparse, grainy, rows lifted |
| 2 | 0.30–0.46 | continuous single pass |
| 3 | 0.46–0.62 | two passes, wider lead |
| 4 | ≥ 0.62 | three passes, hard pressure |

### 11.5 What makes this one world — the continuity, and the client's "natural throughout"

Eleven carriers run unbroken from the black screen to the board. Anything that breaks one of them
is not a style choice; it is the defect the client rejected, returning under a new name.

**C1 · One skirt formula.** Every finite ground object in the film — twelve islands, six worksheet
islets, the theatre disc, the tavern card, the board — stands on the hero's three-band closed lathe
skirt scaled by one number: `SKIRT_D = clamp(radiusZ · 0.439, 0.5, 2.60)`, `k = SKIRT_D / 0.79`. At
the hero's `rz 1.8` this is **identical to four significant figures, not byte-identical** — amended
2026-09-05, because `sets/ground.ts`'s own F14 correction is right and the bible was asserting the
opposite of the builder about the same number: `0.439 · 1.8 / 0.79 = 0.7902 / 0.79 = 1.000253`, so
the formula reproduces the hero's skirt to about a quarter of a millimetre on a 1.8-u card. That is
the honest claim and it is enough for C1; "byte-identical" was not, and in a rule whose authority is
its arithmetic the difference is the whole point. **The film's ground vocabulary is not a
translation of the hero's; it is the same function called with a bigger argument.** Where the
honest scaling gives fewer bands it gives fewer: at worksheet thickness the three collapse to two,
and that is the formula obeying itself rather than a violation of it.

**C2 · The rim contour and its gap.** Every finite ground object ends in an **open drawn arc, never
a closed loop** — `polyline()`, `'form'`, jitter ±0.6% radial and never more (the stroke pipeline's
own wobble is the hand), at `y = 0.012·k`. Every one carries **one deliberate unfinished span**:
≥45° on an elliptical card, ≥1 whole corner on a rectangular one. **Eighteen gaps in the film,
every position authored.** The cliff's 102° gap sits on the north-west quadrant precisely so it
swings into view at S7's rise — the bookend surface shows the visitor its unfinished edge at the
moment the goblin hands the world over, and the flatten begins there. **No rim contour may depend
on the curtain prepass finding an edge.**

**C3 · The ground is one painting.** One `bakeGroundSheet`, 1024², tiling at 4 world units, 256
texels/unit, serves every island in the film that has soil. **There is no second ground painting
and no "dun" variant** — an earth-coloured ground is the incident card's earth field widened, with
the green sheet showing only at the verge.

**C4 · One stroke-angle ladder, and nothing picks off it.**
`0.02` board · `0.04` strata · `0.06` radial floor · `0.10` water · `0.18` sky, cloud and snow ·
`0.30` fields · `0.50 + (seed%5)·0.06` crowns · `0.55 + (seed%4)·0.07` rock, skin and hide ·
`0.61` default · `1.15 + curl·0.12` limbs · `1.35 + (seed%3)·0.05` bark · `1.42` tavern boards ·
`1.45` cloth · `1.50` the tool. Neighbouring props of one class vary by **≤ ±0.2 rad**; more reads
as a second draughtsman. **And the distinction that decides several builds:** a directional *grain*
is a fact of the bake and its UV layout; a *stroke family* is a fact of the draughtsman's sheet. A
24-plank radial disc has 24 grain directions and **one** stroke family.

**C5 · Three tiers, and the adjacency rule.** Every painted mass carries ≥3 separated value tiers
with ≥25 luma between medians, **and no two adjacent surfaces of one object may land in the same
underdrawing tier band.** The second half is the most useful rule in this part: the tier is
computable at authoring time (§11.3), and two adjacent strata both landing in tier 3 draw as **one
flat graphite wall** — which is exactly how a v1 cliff reads under the curtain.

**C6 · Distance is paper, and paper is age.** One depth language, in-material, staged per island:
S1 `8/34` · S2 `4/18` · S3 `6/26` · S4 `7/30` · S5 `3/14` · S6 `5/16` · S7 `10/44`, tightening to
`12/30` for one breath at the rise — the film's one depth move. **No scene fog anywhere, no DOF
pass anywhere.** Because distance ramps toward `paper`, far scenery reads as thinner older coats
and near scenery as the freshest paint with the most wear: **the film's space and its chronology
agree without one extra uniform**, and that is where "a document of its keeping" becomes visible.

**C7 · One backdrop class.** Sky leaves, cloud banks, the S1 treeline bank, the S4 snowy mountain
and the S5 window's view of the undrawn world are **one class** — same geometry, same slot, same Λ
brace, same 0.18 family, two variants (painted trilayer / drawn `MeshBasicMaterial`). Backdrop
flats are honest theatre sheets: **allowed for atmosphere, banned for solid matter**, and they
admit their sheet-nature at every freeze. The sky itself is three things and nothing else — **the
void** (bare paper; `scene.background` stays null and `scene.fog` is deleted), **the air** (the
chapter's token, living in exactly one place in the engine, `rigs.hemi.color`, read off the tops of
rocks, canopies and shoulders and never off the void), and **the leaf**. The value change you see
in a sky is **parallax off the leaf's −0.14 rad rake**, produced by the same in-material ramp that
fades a far tree. It costs one number, and it is the whole answer to "it cannot be a gradient".

**C8 · One wear vocabulary.** Drybrush only where hands go, and three marks with the same recipe on
**every** island: the rubbed landing patch where he always lands (r 0.5 u, `mix(earthTrack, earth,
0.5)` @ 0.30α with 6 committed `earth` dabs), two cart ruts entering at the rim and **stopping** at
0.55 R with a drybrushed stop, and one repair patch exactly one value step off its ground. Twelve
of each in the film. **This is the mark that makes twelve islands read as one commute**, and it
costs three canvas operations per island.

**C9 · One contact ledger.** The hero's exact painted contact blobs — lantern r48 a0.30, signpost
r40 a0.28, mushroom r18–20 a0.26, support stone r22 a0.24, rock r26 a0.24, oak r58 a0.26, pine r50
a0.26, the goblin r24 a0.40 — authored at the hero's 394 texels/unit and scaled per card by *(this
card's texels/unit ÷ 394)*. **Painted props ground. Drawings never do**, in any stage, without
exception. **Zero `contact()` calls anywhere:** a static figure's grounding is a painted blob in
the island's own albedo, which grounds it on both sides of the curtain for free, because the bake
is what the underdrawing derives its tone from.

**C10 · Ink is never a fill.** `ink #222222` appears in this film as **line geometry only** —
`polyline`, `curveLine`, `score`, `numeral`, `mark`, `contourArc`. Every dark mass is a palette
token. The film's darkest painted masses are `gobCloak #272E37` (0.951) and `caveDark #3F3226`
(0.920), and they never sit against each other. The one place tier 4 may fill a large area is the
cave throat, **because a hole in a drawing is density**.

**C11 · Nothing in the world is ever lighter than the page.** `paper #F7F5F0` is the lightest value
in every frame including the night. **The fire is the lightest object; the page is the lightest
value.** That is what keeps eight weathers on one sheet — and it is why a cloud's lit shoulder is
painted as the page showing through at `rgba(paper, 0.85)` rather than as white paint.

**What is allowed to change between stages, and it is a closed list:** the chapter air (hemi colour
only), the key's elevation and intensity within the three committed azimuth families (+18° exterior
day *and* night, +38° interior, none at S8), how many standing sheets are up and their rake, the
ground's hue family via the incident card, poster counts per class, and the local dressing.
**Nothing else.** Structure, stroke ladder, rim grammar, wear vocabulary, contact ledger and value
law are constant from the black screen to the board — and that constancy, not a mood board, is what
"natural throughout the story" means here.

### 11.7 The gates this part must pass

1. **No hatching anywhere.** One stroke family per face, one direction per organic form. The roll
   is **44** — 31 `hatch()` / `crossHatch()` plus 13 `contact()` — and the gate greps both terms to
   zero.
2. **Every colour is a palette token or a two-token `mixHex`.** No fresh hues. `paper #F7F5F0`,
   `ink #222222`, `amber` the only glow, `#B6D648` the wordmark pip alone, goblin-green his alone.
3. **`NoToneMapping` is the judged transfer.** Every tone and tier above was computed under the
   flat transfer. **Nothing here may be judged or tuned under ACES.**
4. **No instancing.** Merge per class per island, transforms baked into vertices — which is also
   what makes `vTriWorld` correct for free.
5. **≤120 draws per stage · ≤40 per-mesh materials · bakes ≤1024² except the board at 1536².**
   Measured in §11.6; the census breach and its one lever are reported, not hidden.
6. **Motion-safe, and this is the test that catches everything else.** Seek to `t` from below and
   from above; the two frames must be byte-identical. Banned: runtime `Math.random`, velocity or
   position integrators, springs, particle simulation of any kind, `deltaTime` or frame count,
   mutating `onUpdate` callbacks, `mod(t, period)` where the wrap is visible, billboards, and
   `visible` flips outside a `tl.set`. Legal: `tl.to` / `fromTo` / `set` on transforms and scalar
   uniforms, `instanceCount` ramps on `LineSegments2`, group scale 0→1→0, pure `f(world.t)`, and
   `steps(n)` eases. **Three clocks and nothing is on two** — `world.t` (freezable, ambient only),
   the master lane (never stops, every authored beat), `gobT` (never stops). Where a thing must move
   inside a freeze it goes on the master lane and the reason is recorded.
7. **Reduced motion is the lit pose, not a damped one.** Every world-clock term takes `ambient` as
   a multiplier on **amplitude only**, so at `a = 0` nothing vanishes and nothing moves.
8. **Framebuffer checks, not opinions.** The night-key readback on the crimson adventurer against
   the pine crown (Δ ≥ 0.12 or restage) · the skin check (human shaded face ≤ 0.45, goblin lit skin
   0.584 ± 0.02, Δ ≥ 0.13) · the graphite-cast check (every figure at `curtain = 1` at 500 px: its
   attribute nameable, its shoulder line findable) · the flame drain check (sweep `curtain` 0→1 in
   0.05 steps; no step may differ from its neighbour by more than 1/16 of the range).
9. **Code-authored geometry and canvas-baked textures only.** No GLTF, no OBJ, no new dependency,
   no image-generation pipeline.
10. **The human frame, which outranks every number above.** S5-B4: three graphite figures caught
    mid-laugh, a graphite die still wobbling, a graphite mug ring, and one painted goblin walking
    through them casting the only shadow in the room. **If that frame does not land, nothing else
    matters.**

### 11.8 Proving a row on screen — the mockup route

A mockup judged alone is how the old world got built. **Every row in §11.2 is proven against the
hero island in the same frame, or it is not proven.**

Two questions the route exists to answer, asked at 500 px with the HUD's draw count visible:
**does this surface look like it was made by the hand that made the island next to it**, and
**does it still read when the curtain drains it to graphite**.

## Appendix — the one-page build order for a new surface

1. **Compute the screen-space arithmetic first.** px/world-unit at the shot's framing,
   texels/unit for any bake, minimum feature size in texels. Write it in a comment.
2. **Build the form, not the primitive.** Overlapping masses or stacked tiers; overlap
   every profile; continue every joint's radius; `roughen()` at 7–22% of the form's radius;
   `DoubleSide` anything the lens can see inside of.
3. **Pick the material family.** Can the seam cross it? → trilayer. Does it live entirely
   in painted territory and read as a drawn prop? → `sketch()` + `paint()`.
4. **Set the trilayer knobs.** `color` (a token, or `0xffffff` with a map), `wear`
   (0.18–0.30), `poster` (**0 unless the class table says otherwise**), `floor` (only with
   poster, only if the mass would otherwise read as a hole), `stroke: { dir, sheet: true }`
   for anything organic.
5. **Author the albedo so its encoded luminance spans ≥ 2 tier bands.** Otherwise the
   drawing is blank.
6. **Author the contours.** In the shot's view plane. Radius 0.99–1.10× the form's own,
   **derived from the geometry**. `'form'` weight. Win depth with a camera push, sized to
   how fast the surface falls away (0.1 at a silhouette, 0.35 into a mass).
7. **Ground it.** Painted contact blob in the ground albedo if it is painted. **Nothing if
   it is a drawing.** Register with `markCaster` only if the full shadow throw clears the
   seam band.
8. **Measure it.** Float readback, both domains, thresholds in `_enc`.
9. **Run `npm run build` and `npm run check`.**
10. **Walk it at four breakpoints with the console open.**
